4. Describe a technical problem you worked on that you found genuinely challenging.
What made it difficult, and how did you approach it?

At RobotQA, the big headache was generating test scripts automatically. Usually, these things are super fragile because they rely on coordinates—one pixel moves and the whole test fails. So, I integrated object detection to give the system "eyes." Making the AI recognize UI elements like a human does, while keeping it fast enough for real-time work, was a massive challenge. But in the end, we cut down the testing time by 70%, which was huge.

More recently at Poilabs, I hit a wall with scaling. We have like 1 million monthly visitors using our indoor maps, and doing all those route calculations on the server was just killing our performance. It was a total bottleneck. My solution was to move the route calculation to the client side. I basically redesigned the whole architecture so the user’s phone handles the heavy pathfinding logic. It took the pressure off our servers and made the navigation feel instant for the users, even if their internet was acting up.

5. When you encounter a system or codebase you don’t fully understand, what do you usually do first?


When I’m dropped into a codebase that looks like a total "black box,"  here’s my go-to process:

    - I usually start with a quick chat with the team members. I don’t want to waste hours guessing something they can explain in five minutes. I’ll ask about the "why" behind the architecture, known pain points, or any weird workarounds I should be aware of.
    - I look at the logs and traces to see how the system behaves.
    - I like to get my hands dirty. I might fix a small typo, improve a variable name, or add a comment while I’m exploring. It ensures I can actually build and deploy the project successfully.
    - If there’s no updated documentation, I’ll draw my own quick diagram of how the services or modules talk to each other.
Basically, I combine the knowledge from the team with the code from the code and logs to get up to speed as fast as possible.
